추론력 높은(비싼) 모델은 계획/분석/설계 단계에 사용하고, 저렴한 모델은 코드 수정·반복 작업·실행에 사용하여 토큰 비용을 최적화한다.

**Why:** 고추론 모델 + 큰 context + Agent/subagent 조합은 토큰 비용이 빠르게 누적. 단계 분리로 *동일 결과물에 더 적은 비용*.

**How to apply:**

1. 고추론 모델로 spec/요구사항 분석 및 작업 계획 수립
2. 계획이 확정되면 사용자에게 *저비용 모델 전환 옵션* 안내 (강제 X — 사용자 결정 따름)
3. 저비용 모델로 실제 파일 수정, 스토리 작성, lint 등 실행 작업 수행
4. 단순 수정/반복 작업에 Agent/subagent 사용도 자제

**모델 매핑 원칙:**

| 구분 | 계획/분석 | 실행/반복 |
| --- | --- | --- |
| 기준 | 사용 가능한 모델 중 추론력과 컨텍스트 처리 능력이 가장 높은 쪽 | 비용이 낮고 반복 수정에 충분한 쪽 |
| 사용처 | 요구사항 해석, 아키텍처, 위험 판단, 리뷰 triage | 파일 수정, 포맷, 단순 테스트 반복, 기계적 변경 |

구체 모델명은 빠르게 바뀌므로 본 룰에 고정하지 않는다. 각 프로젝트나 도구 설정에서 현재 사용 가능한 모델 라인업에 맞춰 매핑한다.

**Caveat:** 저비용 모델 인계 시 기존 피드백/규칙 유지가 약해져 *같은 지적이 반복* 되는 경향. 중요 컨벤션 걸린 복잡 작업은 *고추론 모델 유지* 옵션도 사용자가 선택 가능. **전환 강제 X — 옵션 제시 후 결정 따름.**
