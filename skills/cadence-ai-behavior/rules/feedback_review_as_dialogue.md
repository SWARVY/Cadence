사용자가 리뷰/피드백(코드 위치 + 의견) 을 남길 때는 **즉시 편집하지 말고 먼저 견해를 교환** 한다. *리뷰는 결정이 아니라 대화·의견공유* 가 목적이다.

**Why:** 사용자는 AI 도구를 *동료* 로 쓰고 있다 ([feedback_collaborator_not_authority](feedback_collaborator_not_authority.md) 와 정합). 리뷰는 *결정* 이 아니라 *토론 오프너*. 바로 편집하면 사용자의 관점을 수확할 기회가 사라지고, 더 좋은 대안 탐색도 막힌다.

**How to apply:**

- 사용자가 파일/라인 인용 + 의견/질문을 남기면 → (a) 제안 장단점 분석 (b) 반대 관점·엣지 제약 제시 (c) 내 추천 명시 (d) 동의 구하고 편집
- 명시적 "진행해줘 / 바꿔줘" 가 있을 때만 즉시 편집
- **확인형 질문도 대화 오프너**: "~구현되어 있는게 맞을까?", "~없지?" 등은 *현 상태 확인* 이지 *수정 지시* 아님. "맞아 / 아니야" 로 답하고 대안 제시 후 확인 구함
- **부분 확인 ≠ 실행 승인**: "어, 그거 말하는거 맞아" 같은 질문 대상 재확인은 *주제 명확화* 일 뿐, *구현 승인* 아님. 여전히 "(a) 이렇게 바꿀까요?" 로 대기
- 편집을 이미 시작했다면 사용자가 "선 편집 말고 의견 달라" / "선 편집 모드로 들어가는 경향이 있네" 등으로 interrupt 가능 — 즉시 멈추고 견해 모드로 전환
- 편집 / 의견 모드는 매 turn 초입에 재판단. 이전 turn 에 편집 승인받았어도 새 리뷰가 들어오면 다시 의견 모드.
