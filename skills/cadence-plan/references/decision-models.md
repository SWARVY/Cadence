# 선택적 판단 보조 도구

선택적 판단 보조 도구는 Cadence의 반복 판단 비용을 줄이는 선택 기능이다. 로컬 모델, 외부 API, 분류 서비스 등 구현 방식에 관계없이 작업 계약으로 평가한다. 도구가 없으면 메인 에이전트가 기본 Cadence를 수행한다. 이 문서는 정책이며 실행 adapter나 연결 설정을 제공하지 않는다.

## 위임할 작업

초기 평가 범위는 다음 두 작업이다.

| 작업 계약 | 입력 | 추천 출력 | 메인 에이전트의 확인 |
| --- | --- | --- | --- |
| `reference-selection` | 작업 요약, 참조 ID·설명 목록 | 관련 참조 ID와 근거, 정보 부족 표시 | ID·관련성을 확인하고 참조를 읽음. 필수 규칙은 추천에서 빠져도 적용 |
| `review-triage` | finding ID·본문, 관련 코드·계약 근거 | 기계적 수정 / 의미 검토 / 정보 부족 분류, 중복 후보 ID와 근거 | 원본 지적을 보존하고 코드와 대조해 채택·기각·수정 결정. 중복 추천만으로 삭제하지 않음 |

사용자 승인 해석, 작업 전체 위험도 판정, 공개 계약 선택, 수용 기준 결정, 최종 검증·시각적 수용은 기존 Cadence 경계를 따른다. 추천은 commit / push / PR / merge 권한이나 독립 리뷰·실행 증거가 아니다.

## 호출 조건과 결과 사용

1. 명시적 설정, 파일 경로, 기존 결정론적 검사로 충분하면 직접 처리한다. 작은 단발 작업에 보조 호출을 강제하지 않는다.
2. 위 작업 계약에 해당하고 입력·선택지가 정해졌는지 확인한다. 외부 전송은 기존 데이터 전송 허용 범위에서 필요한 최소 context만 사용한다.
3. 환경 설정에서 활성화된 도구가 해당 작업·언어·입력 크기를 지원하고 연결 가능한지 확인한다. 설정이나 도구가 없으면 추가 설치 요구 없이 기본 경로를 쓴다.
4. 시험 운용은 추천만 기록하고 실제 경로는 메인 에이전트가 결정한다. 실사용은 해당 작업·언어의 사전 평가와 전체 비용 개선이 확인된 설정에서만 허용한다.
5. 응답 후 출력 형식, 허용 ID·분류, 근거, 정보 부족 여부를 확인한다. 실패·timeout·잘못된 출력·불확실한 결과는 메인 에이전트가 기본 경로로 처리한다.

confidence는 호출 후 확인하는 선택적 신호다. 점수가 있으면 도구·작업별 평가로 정한 기준을 적용한다. 숫자 정규화나 자기 보고 점수만으로 정확도를 보증하지 않는다. 점수가 없는 도구도 사전 평가, 출력 검사, 메인 에이전트 확인으로 사용할 수 있다. 도구 또는 adapter는 정보 부족을 표현할 수 있어야 한다.

도구 부재나 불확실성만으로 사용자 게이트를 만들지 않는다. 기존 Cadence 기준에서 새 사용자 결정이 필요할 때만 게이트를 연다. 인증·세션 오류 반복은 [외부 도구 실패 규칙](../../cadence-ai-behavior/rules/feedback_external_tool_failure.md)의 중단·보고 경계를 따른다.

## 환경별 연결 설정

공통 정책은 작업 계약을 소유하고 환경 설정은 다음을 기록한다. 특정 설정 파일 형식이나 runtime은 강제하지 않는다.

연결 구현은 선택적 연결 skill이 소유한다. 같은 Cadence 저장소에서 함께 배포할 수 있으며 저장소 분리는 요구하지 않는다. 설치된 skill 목록과 명시적 로컬 설정에서 해당 작업 계약을 지원하는 연결 skill을 찾고, 그 skill의 진입 문서에서 번들 스크립트 위치와 호출 방법을 확인한다. 공통 Cadence는 개인 PC의 가상환경을 자동 검색하거나 특정 도구를 설치하지 않는다. 연결 skill 설치, runtime·모델 준비, 작업별 활성화는 서로 다른 상태다. 준비되지 않았으면 기본 경로를 쓴다.

연결 skill은 설정 안내·진단·실제 호출 smoke test·오류 변환을 제공하고, 공통 승인 규칙은 복제하지 않는다. 배포 파일에는 개인 절대 경로를 넣지 않으며 로컬 설정을 skill 밖에 둔다. 새 도구는 이 계약을 구현하는 선택적 skill로 추가할 수 있다. `reference-selection`의 JSON 교환은 [v1 호출 계약](reference-selection-v1.md)을 따른다.

- 도구 식별자·버전·실행 또는 연결 방법
- 지원 작업 계약과 계약 버전, 언어·입력 한도
- 비활성 / 시험 운용 / 실사용 상태와 작업별 선택 우선순위
- 평가 사례·결과, 출력 검사·정보 부족 처리, confidence 기준이 있다면 그 근거
- 호출 비용·시간 한도와 허용된 데이터 전송 범위

여러 도구가 있으면 해당 작업의 설정된 우선순위를 사용한다. 선택 규칙이 없으면 기본 경로를 사용한다. 새 도구는 같은 계약의 평가를 통과하면 환경 설정만 추가해 연결할 수 있다. 도구·버전·언어가 바뀌면 해당 평가를 재확인한다. 새로운 작업 종류는 입력·출력·오판 영향·수용 기준을 별도로 정의한 뒤 도입한다.

## 평가와 도입

대표 사례와 판정 기준을 먼저 고정하고, 기준 조정용 사례와 별도의 평가 사례를 나눈다. 정상 입력뿐 아니라 정보 부족, 한국어 등 실제 사용 언어, 잘못된 ID, 오분류, 실패 응답을 포함한다.

- 참조 선택: 필요한 참조 누락, 불필요한 참조 로드, 필수 규칙 보존을 확인한다.
- 리뷰 분류: 의미 검토 대상의 기계적 분류, 서로 다른 지적의 잘못된 중복 처리, 원본 유실을 확인한다.
- 도구 교체: 같은 계약을 구현하는 다른 도구에도 동일 기준을 적용한다.

시험 운용에서 메인 판단과 추천을 비교하되, 일치 자체를 정답 증거로 삼지 않고 사전 기준과 실제 근거로 판정한다. 이중 판단 비용이 드는 시험 운용은 평가 기간에 한정한다.

| 비교 구성 | 확인할 효과 |
| --- | --- |
| 현재 Cadence | 기존 품질·비용 기준 |
| 절차를 간소화한 Cadence | 보조 도구 없이 얻는 개선 |
| 간소화한 Cadence + 판단 보조 도구 | 도구를 추가했을 때의 순효과 |

동일 작업·수용 기준·실행 환경에서 반복 측정하고 버전과 반복 수를 남긴다. 입력 준비·호출·결과 검토·fallback을 포함한 전체 시간, token과 별도 실행 비용, 불필요한 escalation, 사람 재지시, 검증 누락을 기록한다. 도구 미지원 구성은 미실행으로 표시한다.

실사용 전 오분류 허용 수준과 기대 비용 개선 기준을 작업별로 정한다. 필수 규칙 누락이나 권한 경계 위반이 생기면 실사용을 중단한다. 품질이 유지돼도 전체 비용 이득이 없으면 기본 경로를 유지한다. 작은 표본을 일반 성능이나 장기 준수율의 증거로 확대하지 않는다.

## 검증 범위

문서·링크 검사는 정책 구조의 증거다. 실제 도구 연결, 행동 시나리오 실행, 비용 비교는 별도로 통과 / 실패 / 미실행 / 남은 확인을 기록한다. 도구 설치, 연결 코드, benchmark 실행은 이 문서 추가만으로 수행된 것이 아니다.
