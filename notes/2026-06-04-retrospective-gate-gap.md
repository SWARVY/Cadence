# 회고 가치 평가는 출력되지만, 회고 작성 결정이 강제되지 않아 학습 기록이 작업에 밀린다

## 무엇이 일어났나

여러 작업에서 PR merge, 방향 전환, 도구 선택 변경, 런타임 이슈 대응이 반복됐지만 가치가 있다고 평가된 회고가 실제 문서로 남지 않았다.

현재 cadence-retrospective 규칙은 PR merge 직후 `회고 가치 평가: 낮음 / 중간 / 높음` 출력은 mandatory 로 정의한다. 하지만 회고 파일 생성은 사용자 합의 후로 분리되어 있고, 중간/높음 평가 이후에도 다음 작업을 바로 시작할 수 있다.

그 결과 실제 대화에서는 다음 흐름이 반복됐다.

1. PR merge 직후 회고 가치 평가를 출력한다.
2. 회고 후보를 제안한다.
3. 사용자가 바로 다음 작업을 요청하거나, AI 가 다음 작업으로 넘어간다.
4. 회고 후보는 문서로 남지 않는다.
5. 같은 종류의 workflow gap 이 다시 발생한다.

## 왜 문제인가

cadence 의 목적은 작업을 느리게 만드는 것이 아니라, 되돌릴 수 있는 지점에서 의사결정과 학습을 남기는 것이다.

하지만 현재 회고 단계는 “평가 출력”과 “문서 작성” 사이에 결정 게이트가 없다. 그래서 회고 가치가 중간/높음이어도 실제로는 제안형 알림에 가깝게 동작한다.

특히 “머지하고 다음 작업 시작”처럼 연속 지시가 들어오면, AI 는 merge 와 다음 작업 사이에 평가만 끼워 넣고 실제 회고 작성 여부를 확정하지 않은 채 넘어가기 쉽다.

## 근본 원인

- 회고 가치 평가는 mandatory 이지만, 중간/높음 평가 이후의 후속 행동은 optional 에 가깝다.
- “사용자 합의 후 작성” 원칙이 “사용자에게 묻지 않고 생략 가능”으로 해석될 여지가 있다.
- 회고 후보 상태를 추적하거나 보류 목록에 남기는 규칙이 없다.
- 다음 작업을 시작하기 전, 회고를 작성 / 보류 / 생략 중 하나로 명시 결정해야 한다는 게 skill 에 충분히 강하게 박혀 있지 않다.

## 기대하는 동작

PR merge 직후 또는 작업 완료 직후 회고 가치가 중간/높음이면, 다음 작업을 시작하기 전에 반드시 아래 셋 중 하나를 결정해야 한다.

1. 회고 문서 작성
2. 회고 후보로 보류
3. 명시적으로 생략

`높음`인 경우 기본 제안은 “회고 초안 작성”이어야 한다. 자동 커밋/푸시는 하지 않더라도, 초안 파일을 만들지 여부를 사용자에게 명확히 확인해야 한다.

## 제안하는 룰 변경

`cadence-retrospective`에 다음 규칙을 추가한다.

```text
회고 가치가 중간/높음이면 다음 작업 시작 전 회고 처리를 닫아야 한다.

- 작성: 회고 초안 파일을 만들고 INDEX 갱신 여부를 확인한다.
- 보류: 회고 후보 제목과 근거를 명시적으로 남긴다.
- 생략: 사용자가 생략을 명시했음을 기록하고 다음 작업으로 이동한다.

AI 는 중간/높음 평가를 출력한 뒤 곧바로 다음 구현으로 넘어가면 안 된다.
```

## 수용 기준

- PR merge 직후 `회고 가치 평가: 중간` 또는 `높음`이 나오면, AI 응답에 작성 / 보류 / 생략 결정이 반드시 포함된다.
- 사용자가 “머지하고 다음 작업 시작”이라고 해도, merge 와 다음 작업 사이에 회고 처리 게이트가 닫힌다.
- 높은 가치의 회고가 2회 이상 연속으로 문서화되지 않는 상황을 방지한다.
- 회고 파일 생성은 여전히 사용자 합의 후 진행하되, 합의 여부 자체는 명시적으로 확인된다.

## 일반화된 관찰 신호

- 구현 접근이 중간에 바뀌거나 기존 선택을 큰 폭으로 회수했는데도 학습이 대화에만 남는다.
- 디자인, 라우팅, 런타임, 외부 도구처럼 다른 작업에도 재발할 수 있는 문제가 단발성 수정으로 끝난다.
- 회고 후보를 제안했지만 처리 상태를 닫지 않아 다음 작업에 밀린다.

## 후속 반영 (2026-08-04)

[행동 전환점 재판정 회고](./2026-08-04-transition-preflight-enforcement-gap.md)에서 회고 처리 게이트와 작성 내부 phase를 다시 분리했다.

- `작성 / 보류 / 생략` 결정은 다음 작업 전 닫는다.
- `작성`이 승인되면 본문·INDEX·확인 가능한 로컬 역참조는 같은 승인 범위에서 완료한다.
- 본문 작성 뒤 INDEX 갱신을 위해 같은 진행 승인을 반복하지 않는다.
- 룰 승급과 commit·push는 별도 승인으로 유지한다.

따라서 위 초기 제안의 “INDEX 갱신 여부를 다시 확인”하는 절차는 최신 `cadence-retrospective`에서 대체됐다.
