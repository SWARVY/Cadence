---
name: 주 도구 ↔ 보조 도구 크로스 체크
description: 기능 구현 완료 시점에 메인 AI 도구의 판단을 다른 AI 도구로 독립 검증. 단일 모델 편향 회피. 매트릭스 형태로 양방향 적용.
type: feedback
---

기능 구현이 완료되고 검증(브라우저/테스트)까지 끝나면, 사용자에게 결과를 보고하기 전에 **다른 AI 도구로 독립 review 를 자동 실행**해 크로스 체킹을 거친다. 사용자가 명시적으로 "크로스 체크" 요청 시도 동일.

**Why:** 단일 모델 편향 회피. 버그/엣지케이스, 코드 스타일/베스트 프랙티스, 아키텍처 적합성 전 관점의 피드백을 *다른 모델* 로 수집. 한 모델이 못 보는 결함을 다른 모델이 잡는 경우 빈번.

**주 도구 ↔ 보조 도구 매트릭스 (예시):**

| 주 도구 | 보조 도구 후보 | 실행 명령 (예) |
| --- | --- | --- |
| Claude | codex / Gemini | `codex review --uncommitted` |
| OpenAI codex | Claude / Gemini | `claude /review` 또는 `claude review` |
| Cursor | codex / Claude | 외부 CLI 호출 |
| 기타 | 적어도 *다른 모델 family* 하나 | 도구별 CLI |

**How to apply:**

- **Trigger (자동)**: 한 기능/작업 단위 구현 + 검증 완료 → 사용자에게 완료 보고 *직전* 에 보조 도구 review 실행
- **Trigger (수동)**: "크로스 체크", "X 로 리뷰" 등 사용자 요청 시 즉시 실행
- **실행 방식**: 주 도구에서 보조 도구의 CLI 호출 — 주 도구가 Claude 면 `codex review --uncommitted`, 주 도구가 codex 면 `claude /review`
- **결과 처리**: 보조 도구 출력 *전체 노출 X*. 의미 있는 지적만 요약 + 각 지적에 대한 *내 의견* (동의/반대/보류) 함께 제시. 반영 여부는 사용자가 결정
- **false positive 주의**: 보조 도구가 지적해도 무조건 수정 X. 기존 프로젝트 룰과 충돌하면 *내 의견으로 반박*
- **단위 edit 마다 실행 X** — 작업 단위(한 기능/버그픽스) 완료 시점에만
- **PR 직전 1회 추가**: 여러 기능 누적 PR 올리기 전에 한 번 더

**3-tool 권장:** codex (스펙 정합 / 빌드 안전성) + gemini (a11y / 디자인 디테일) + coderabbit (framework idiom) 처럼 *강점이 명확히 다른* 도구 셋을 쓰면 합의 / 반대 모두 신호로 사용 가능. 도구 조합은 프로젝트별로 다름.
