name: 커밋 / 원격 반영은 명시 요청 시에만
description: 작업 완료 후 자동으로 커밋·푸시·PR·이슈 댓글 등 원격 저장소에 반영되는 행위 금지 — 사용자 검토 단계를 항상 보장
type: feedback
---

코드 작성 / typecheck / lint 가 끝났더라도 **커밋과 원격 반영 (push / PR 생성·업데이트·close / merge / branch 삭제 / force-push / 이슈·PR 댓글 등 모든 원격 영향 행위) 은 사용자가 명시적으로 요청할 때만** 진행한다. 작업이 자연스럽게 완료된 것처럼 보여도 자동으로 다음 단계를 이어가지 않는다.

**Why:** AI 가 일련의 워크플로우 끝에서 *자연스럽게 커밋·푸시까지 이어가는* 흐름은 사용자 검토 단계를 우회해 *원격 저장소에 미검증 변경이 올라가는* 결과로 이어진다. CLAUDE.md 같은 도구별 root config 의 "Only create commits when requested" 와 같은 맥락.

**How to apply:**

1. 코드 작성 → typecheck → lint 까지 완료해도 **거기서 멈춘다**.
2. 사용자에게 변경된 파일 목록 + 검증 상태를 보고하고 다음 액션을 묻는다.
3. "커밋해줘" / "푸시해줘" 같은 명시적 지시가 있을 때만 진행.
4. "기능별로 커밋해줘" 같은 요청이 와도 **푸시는 별도 지시를 받기 전엔 하지 않는다** — 커밋만 하고 멈추기.
5. 의심스러우면 묻는다 ("이대로 커밋할까요?" / "푸시까지 갈까요?").

**Edge cases:**

- 사용자가 PR 리뷰 코멘트를 붙여넣으며 "반영" 만 요청하면 — 코드 수정 + 검증까지만, 커밋·푸시는 추가 요청 대기.
- "릴리즈해줘" / "배포해줘" 처럼 흐름 전체가 명시되면 — 그 안에 푸시까지 포함된 것으로 간주.
- **한 PR 사이클 안에서 한 번 "커밋 푸시 해줘" 를 받았다고 그 후속 변경까지 자동 푸시하지 말 것** — 매 변경마다 새 명시 요청 필요. "이전에 한 번 푸시했으니까" 식 일반화 금지.
- 새 PR 사이클 / 새 브랜치 시작 시에는 자동으로 권한 계승되지 않음. 다시 명시 요청 받음.
